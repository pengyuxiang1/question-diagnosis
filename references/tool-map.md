# 工具决策 Map（骨架 · 请按你的环境填写）

> **用法**：拿到问题现象 → 在表里找最接近的一行 → 按「先查什么 → 用什么工具」执行。
> 不要凭直觉查——花 10 秒查表，避免"查了半天发现方向错了"。
>
> 📌 OKF 时效约定：填入真实工具后，把 frontmatter 改为 `status: stable` + `verified: 今天日期`；含具体 URL/路径/版本的内容必须填 `stale_after`（建议一年）——过期的工具信息比没有更危险。

## 填表建议

1. **按「现象」组织，不要按工具组织**——排查时是带着现象来的，不是带着工具来的
2. 每行给**可执行的**入口（命令、链接、工具名），不写"看日志"这种模糊动作
3. 踩过坑后回来补「备注」列（时间窗限制、索引选择、常见陷阱、数据延迟）
4. 这张表本身就是排查经验的一部分——每次归档案例（Step 6）时回看一眼有没有要补的行
